# 3. 정책과 시나리오

코드가 따라야 하는 요구사항이다. 규칙은 이 문서에만 두고, 다른 문서와 테스트는 규칙 ID로 가리킨다.

## 불변식

- **수량**: 판매 수량 = 남은 수량 + 잡아 둔 수량 + 확정된 수량
- **결제**: 상품을 받지 못한 구매에 결제가 남아 있지 않다.

## 수량 규칙

| ID | 규칙 |
|---|---|
| Q1 | 판매 시작 시각 전의 구매 시도는 거절한다. |
| Q2 | 동시에 들어온 구매의 결과는 요청을 한 줄로 세워 하나씩 처리한 것과 같다. 시간이 겹치지 않게 온 요청은 먼저 도착한 요청이 먼저 수량을 받고, 거의 같은 순간에 온 요청끼리 순서가 뒤바뀐 경우(역전)는 잰다. |
| Q3 | 같은 구매자의 반복 시도는 구매 하나로 처리한다. 여러 탭과 기기도 같은 구매자로 보며, 1인 한도는 구매자의 구매 합계로 지킨다. |
| Q4 | 잡아 둔 수량은 확정 또는 반환 중 하나로만 끝난다. |
| Q5 | 수량이 돌아오는 경우(시간 초과, 결제 거절, 결제사 오류)는 모두 같은 규칙으로 돌려놓고, 품절 뒤에도 다시 판다. |

## 결제 규칙

결제를 시작할 수 있는 기한(잡아 둔 뒤 5분)과 결과를 기다리는 기한(확인 기한)은 따로 둔다.

| ID | 상황 | 처리 |
|---|---|---|
| P1 | 5분 안에 결제 요청이 도착함 | 받아들이고 결과를 기다린다 |
| P2 | 결제가 진행 중인데 같은 구매에 결제 요청이 또 옴 | 거절한다. 결제는 한 번에 하나다 |
| P3 | 결제 승인 | 구매를 확정한다. 5분이 지났더라도 5분 안에 받아들인 결제라면 인정한다 |
| P4 | 결제 거절, 아직 5분 안 | 수량을 유지하고 다시 결제할 수 있다 |
| P5 | 결제 거절, 5분이 지남 | 수량을 돌려놓는다 |
| P6 | 5분이 지나도록 결제 요청이 없음 | 수량을 돌려놓는다 |
| P7 | 결과를 바로 모름 | 구매자에게 "결제 확인 중"을 알리고, 결제사에 다시 확인하며 확인 기한까지 기다린다. 구매자는 구매 상태를 조회해 결과를 확인한다 |
| P8 | 확인 기한까지도 결과를 모름 (결제사 오류) | 구매는 실패로 끝내고 수량을 돌려놓으며, 구매자에게 결제사 오류로 구매하지 못했다고 안내한다. 결제는 실패로 단정하지 않고 계속 확인한다. 실패로 확인되면 끝내고, 승인으로 확인되면 구매를 되살리지 않고 결제를 취소한다 |

## 경계와 재처리 규칙

| ID | 규칙 |
|---|---|
| T1 | 시각은 요청이 도착해 기록된 시각을 기준으로 하고, 기한이 지났는지는 기한 시각으로 판단한다. 만료 처리가 아직 실행되지 않았어도 기한 뒤에 기록된 요청은 무효다. |
| T2 | 같은 구매에 대한 반영은 차례로 일어나며, 만료 처리는 기한 전에 받아들인 결제가 없을 때만 수량을 푼다. |
| R1 | 수량 반환, 결제 결과 조회, 결제 취소는 반복하거나 동시에 실행해도 결과가 같다. 재시도 간격은 점점 늘리고, 한계를 넘으면 미해결로 드러낸 채 계속 시도한다. 미해결은 완료가 아니다. |

## 정하지 않은 것

설계에서 정한다. 정하기 전에는 구현에서 임의로 확정하지 않는다.

- 확인 기한의 길이 (P7, P8)
- 재시도 간격과 미해결로 드러내는 기준 (R1)
- 응답을 못 받은 구매자가 같은 결제 요청을 다시 보낸 경우와 새 결제 시도의 구분 (P2)
- 순서를 정하는 "도착" 시점을 어디서 기록하는지 (Q2)

## 시나리오

모두 테스트로 확인한다. 수량 불변식은 테스트마다 공통 검사로 확인하고, 결제 불변식은 재처리를 마친 최종 상태에서 확인한다. 미해결(R1)은 결제 불변식을 아직 만족하지 못한 상태로 드러난다. 테스트에서는 시각을 조절할 수 있어야 하고, 결제사 대역은 거절, 무응답, 늦은 승인, 취소 실패를 만들 수 있어야 한다.

### A. 수량 확보

| | 상황 | 기대 결과 | 규칙 |
|---|---|---|---|
| A1 | 판매 시작 순간 수량보다 훨씬 많은 구매자가 동시에 시도 | 성공 수 = 판매 수량, 초과 판매 0 | Q2 |
| A2 | 마지막 1개에 여러 명이 동시에 시도 | 1명만 성공, 나머지는 품절 | Q2 |
| A3 | 같은 구매자가 같은 구매를 동시에 여러 번 보냄 | 구매 하나 | Q3 |
| A4 | 같은 구매자가 구매를 나눠 동시에 보내 한도를 우회 | 합계가 한도 이하 | Q3 |
| A5 | 판매 시작 전에 시도 | 거절 | Q1 |
| A6 | 잡아 둔 수량이 결제 시작 기한을 넘김 | 수량이 돌아오고 다른 구매자가 살 수 있음 | P6, Q5 |
| A7 | 수량이 돌아오는 순간 새 구매가 동시에 들어옴 | 수량이 어긋나지 않음 | Q5 |
| A8 | 남은 수량보다 많은 구매자가 시간이 겹치지 않게 차례로 시도 | 먼저 온 순서대로 수량을 받음 | Q2 |

### B. 결제 확정

| | 상황 | 기대 결과 | 규칙 |
|---|---|---|---|
| B1 | 기한 안에 결제 승인 | 확정 | P3 |
| B2 | 거절된 뒤 기한 안에 다시 결제해 승인 | 확정 | P4, P3 |
| B3 | 결제 진행 중에 같은 구매의 결제 요청이 또 옴 | 거절 | P2 |
| B4 | 기한 직전에 받아들인 결제가 기한 뒤에 승인 | 확정. 그 사이 수량은 풀리지 않음 | P3, T2 |
| B5 | 기한이 지난 뒤 결제 요청 | 거절, 수량 반환 | T1, P6 |
| B5a | 기한이 지난 뒤 결제 요청, 만료 처리는 아직 실행 전 | 거절, 수량 반환 | T1 |
| B6 | 결제 요청과 기한 만료가 동시에 일어남 | 둘 중 하나만: 결제 진행과 수량 유지, 또는 결제 거절과 수량 반환 | T2 |
| B7 | 결제사 무응답 → 확인 기한 안에 조회해 보니 승인 | 먼저 "결제 확인 중"을 받고, 이후 구매 상태를 조회하면 확정 | P7 |
| B8 | 승인 확인과 확인 기한 만료가 동시에 일어남 | 둘 중 하나만: 확정, 또는 구매 실패·수량 반환·결제 취소 대상 | P8, T2 |
| B9 | 확인 기한까지 결과를 모름 → 나중에 승인으로 확인 | 구매 실패, 수량 반환, 결제 취소 완료 | P8 |
| B9a | 확인 기한이 지난 뒤 승인 확인, 기한 만료 처리는 아직 실행 전 | B9와 같음 | P8, T1 |
| B10 | 결제 취소가 일시적으로 실패한 뒤 결제사가 회복 | 다시 요청해 취소 완료 | R1 |
| B11 | 결제 취소가 계속 실패해 한계를 넘음 | 미해결로 드러나고 시도는 계속됨. 구매자는 "구매 실패, 결제 취소 처리 중"을 봄 | R1 |
| B12 | 같은 수량 반환이나 결제 취소를 중복 또는 동시에 실행 | 수량은 한 번만 돌아오고, 결제사에는 취소가 한 번만 반영됨 | R1, Q5 |

## C. 몰림 상황의 측정

판매 시작 순간 많은 구매자가 몰리는 상황에서 아래 구간의 시간 분포를 따로 잰다. "결제 확인 중"으로 응답한 비율과 Q2의 역전 수와 폭도 함께 기록한다.

| 구간 | 끝나는 시점 |
|---|---|
| 구매 시도 → 결과 | 수량 확보, 품절, 한도 초과 중 하나를 받음 |
| 결제 요청 → 첫 응답 | 승인, 거절, "결제 확인 중" 중 하나를 받음 |
| 결제 요청 → 최종 결과 | 구매가 확정 또는 실패로 정해짐 |
| 구매 시도 → 최종 결과 | 구매 전체 |

첫 응답만 빨라진 것은 개선이 아니다. 최종 결과까지의 시간이 나아지고, 같은 측정에서 수량 불변식이 유지되고 역전이 늘지 않을 때 개선으로 본다. 측정 조건과 결과는 [실험 기록](CONTRIBUTING.md#문서-관리)에 남긴다.
