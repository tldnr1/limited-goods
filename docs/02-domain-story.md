# 2. 도메인 스토리

## 참고한 판매

- **포켓몬센터 온라인**: 인기 상품 발매일에 가상 대기실을 둔다. 판매 시작 전 30분 동안 접속한 사람의 입장 순서를 추첨하고, 시작 시각부터 그 순서대로 들여보낸다. 그 뒤에 온 사람은 추첨 대상자 뒤에 선착순으로 선다. 순서가 온 뒤 10분 안에 들어오지 않으면 순서가 무효가 되고, 입장 후 이용 시간은 약 20분이다. 장바구니에 담은 시점에는 재고를 확보하지 않고 주문이 완료되어야 확정한다. ([대기실 공지](https://www.pokemoncenter-online.com/news/?id=20260908), [대기실 FAQ](https://www.support.pokemoncenter-online.com/%E4%BB%AE%E6%83%B3%E5%BE%85%E5%90%88%E5%AE%A4-67614f5a2b619c20358a84c1), [주문 안내](https://www.pokemoncenter-online.com/guide/guide-order.html))
- **스트리머 굿즈 판매**: 한 행사에 수량이 한정된 품목과, 수량은 넉넉하지만 1인 한도가 있는 품목(엽서 등)이 섞여 있다.
- **콘서트 티켓 예매**: 좌석을 잡은 뒤 제한 시간 안에 결제한다.

## 행위자와 대상

- **구매자**: 이미 가입되어 있으며, 누구인지만 구분한다.
- **운영자**: 행사, 품목, 판매 수량, 1인 한도, 판매 시작 시각을 미리 등록해 둔다.
- **결제사**: 외부에 있다. 결제를 승인하거나 거절하고, 결과 조회와 취소 요청을 받는다.
- **대상**: 행사, 품목, 판매 수량, 1인 한도, 구매, 구매자 몫으로 잡아 둔 수량, 결제

## 핵심 흐름: 선착순 구매

행사와 품목은 이미 등록되어 있고, 처음에는 1인 한도가 있는 품목 하나를 판다.

1. 판매 시작 시각이 되면 여러 구매자가 동시에 구매를 시도한다.
2. 구매를 먼저 시도한 사람이 먼저 수량을 받는다. 순서는 구매 요청이 도착한 순서다. 받은 수량은 그 구매자 몫으로 잡아 둔다.
3. 1인 한도를 넘으면 거절하고, 남은 수량이 없으면 품절을 알린다.
4. 구매자는 결과가 나올 때까지 기다렸다가 바로 받는다: 수량 확보(5분 안에 결제), 품절, 한도 초과.
5. 구매자가 5분 안에 결제를 요청하고, 결제사가 승인하면 구매가 확정된다.
6. 5분 안에 결제하지 않으면 잡아 둔 수량이 풀리고, 다른 구매자가 다시 살 수 있다.

## 결제 시간 규칙

시각은 결제 요청이 도착한 시각을 기준으로 한다. 결제를 시작할 수 있는 기한(잡아 둔 뒤 5분)과 결과를 기다리는 기한(확인 기한)은 따로 둔다.

| 상황 | 처리 |
|---|---|
| 5분 안에 결제 요청이 도착함 | 받아들이고 결과를 기다린다 |
| 결제가 진행 중인데 같은 구매에 결제 요청이 또 옴 | 거절한다. 결제는 한 번에 하나다 |
| 결제 승인 | 구매를 확정한다. 5분이 지났더라도 5분 안에 받아들인 결제라면 인정한다 |
| 결제 거절, 아직 5분 안 | 수량을 유지하고 다시 결제할 수 있다 |
| 결제 거절, 5분이 지남 | 수량을 돌려놓는다 |
| 5분이 지나도록 결제 요청이 없음 | 수량을 돌려놓는다 |
| 결과를 모름 | 결제사에 다시 확인하며 확인 기한까지 기다린다 |
| 확인 기한까지도 결과를 모름 | 아래 "결제사 오류" 참고 |

**결제사 오류**: 확인 기한까지 결과를 모르면 구매는 실패로 끝내고 수량을 돌려놓는다. 구매자에게는 결제사 오류로 구매하지 못했다고 안내한다. 결제는 실패로 단정하지 않고 계속 확인한다. 실패로 확인되면 끝내고, 승인으로 확인되면 구매를 되살리지 않고 결제를 취소한다. 취소가 확인될 때까지 다시 요청한다.

이 규칙이 지키려는 것은 하나다. **상품을 받지 못한 구매에 결제가 남아 있지 않다.**

## 예외 상황

- 같은 구매자가 여러 번 누르거나 새로고침함 → 구매 하나로 처리한다.
- 여러 탭이나 여러 기기에서 시도함 → 같은 구매자로 본다. 1인 한도는 구매자 기준이다.
- 나눠서 구매해 한도를 우회함 → 구매 합계로 한도를 지킨다.
- 결제 거절, 결과를 모름, 시간 초과 → 결제 시간 규칙을 따른다.
- 수량이 돌아오는 경우(시간 초과, 결제 거절, 결제사 오류)는 모두 같은 규칙으로 돌려놓고, 품절 뒤에도 다시 판매한다.

## 고도화 주제

지금 만들지 않는다. 나중에 더할 수 있다는 것만 전제로 두고, 지금 무엇을 준비할지는 5단계 설계에서 정한다.

**여러 품목**
- 한 행사 안에 수량 한정 품목과 1인 한도만 있는 품목이 섞인다. 행사끼리는 섞지 않는다.
- 장바구니는 두지 않는다. 한 번의 구매 시도에 여러 품목을 담는다.
- 1인 한도는 품목마다 따로 둔다.
- 담은 품목 중 하나라도 확보하지 못하면 구매 전체가 실패한다. 구매자는 그 품목을 빼고 다시 시도한다.

**입장 제어**
- 동시에 구매 화면에 머무는 사람 수는 판매가 감당할 수 있는 양과 이어진다. 그래서 들어오는 사람을 조절한다.
- 판매 시작 전 대기실에 들어온 사람 중에서 입장 순서를 무작위로 정하고, 그 뒤에 온 사람은 선착순으로 선다.
- 입장한 뒤 20분 안에 구매를 마쳐야 한다. 아무것도 하지 않은 사람은 시간이 지나면 나가고 다음 사람이 들어온다.
- 공정함의 기준은 "입장 순서는 추첨으로, 입장 뒤에는 시도한 순서대로"다.

## 다루지 않는 것

- 구매자가 요청하는 환불. 수량을 돌려놓는 규칙을 하나로 모아 두어, 나중에 더할 때 같은 규칙을 쓴다.
- 봇과 부정 구매 방지
- 회원 가입, 행사와 품목 등록 과정

## 4단계에서 정할 것

- 확인 기한의 길이
- 결제 취소를 몇 번까지 다시 요청하고, 그 뒤 어떻게 처리할지
