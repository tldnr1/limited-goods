# ADR-0007. 결제 결과 재확인은 재처리만 하고, 확인 기한 전 마지막 조회를 보장한다

- 상태: 채택

## 맥락

결제 결과를 바로 모르면 구매자는 "결제 확인 중"을 보고 상태를 조회한다(P7). 앱이 결과를 알게 된 시각이 확인 기한 뒤면 결제사가 기한 전에 승인했어도 구매는 실패한다(P8, B9a). 몰림 상황에서는 결과 대기 결제와 상태 조회가 함께 늘어난다.

## 결정

- 결제사 조회는 재처리 스케줄러만 한다. 구매자의 상태 조회는 DB만 읽는다.
- 구매가 잡아 둠인 동안 다음 확인 시각을 `확인 기한 − (호출 제한 시간 + 재처리 주기)`보다 늦지 않게 잡아, 기한 전 마지막 조회를 보장한다.

## 고르지 않은 대안

- 상태 조회가 결제사 조회를 일으킴: 구매자가 결과를 빨리 볼 수 있지만, 반복 조회만큼 결제사 호출이 늘고 같은 결제를 재처리와 동시에 확인하게 된다.
- 간격만 늘려 가며 확인: 단순하지만 기한 직전의 조회 기회가 간격에 따라 달라져, 같은 결제사 지연에도 결과가 달라진다.

## 결과

- 결제사 호출 수는 결과 대기 결제 수와 재시도 간격으로 정해지고, 구매자의 조회 빈도와 무관하다.
- 구매자가 결과를 보는 시점이 재확인 간격과 재처리 주기에 묶인다. C의 "결제 요청 → 최종 결과" 구간으로 잰다.
